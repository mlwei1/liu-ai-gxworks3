# 产品闭环

## 用户视角的五个动作

1. **导入历史程序**：选择自己工程的"程序本体 CSV + 软元件注释 CSV"（GX Works3 导出）。
   软件分析出你的风格画像：段结构、步号段、模式位、报警布局、命名习惯、握手信号写法、指令构成。
2. **输入需求**：中文描述工位/动作/互锁，上传 IO 表（或粘贴 CSV）。
3. **生成初稿**：软件先给"程序架构方案"（ProgramSpec：段清单、步号段、IO 分配、握手信号、待确认问题），
   用户确认/修改后才生成正式程序。
4. **检查/修改**：软件展示段 → 网络 → 指令/注释，导出程序本体 CSV + 注释 CSV；
   用户在 GX Works3 导入、全部转换、修编译错误、补逻辑。
5. **告诉软件哪里错了**：在软件里对某段/某网络标注错误类型与说明（可附修正说明）。
   下轮生成时，这些经验进入规划提示、检查清单和修正样例；同类问题不该重复出现。

## 反馈如何"让软件下次优化"（不训练模型）

| 反馈类型 | 落点 |
|---|---|
| 段结构/顺序不对 | 写入该项目的 `lessons`，并调整 StyleProfile 的段模板 |
| 命名/注释不符 | 更新 StyleProfile 命名规则；生成器优先使用 |
| 缺互锁/缺报警/缺停止 | 作为规则检查项 + 规划提示词清单 |
| 某网络逻辑错误 | 记录"错误模式 → 正确写法"样例，作为 LLM few-shot / 模板候选 |
| 用户直接修改了 spec/程序 | 保存为"修正样例"，下一轮作为参考 |

> 原则：优化 = 规则/模板/画像/样例库的确定性更新 + LLM 提示词注入，不做模型微调。

## 风格学习边界

- 输入：GX Works3 导出的程序本体 CSV + 软元件注释 CSV（支持多文件）。
- 输出：`StyleProfile`（见 `spec/style_profile.schema.json`）。
- 用途：生成器默认段顺序、步号段分配、模式位映射、报警基址、命名模板、注释风格；
  规划器提示词摘要。
- 不做：逐字节复刻用户程序；不复制用户私有逻辑到其他项目（画像只保留统计/模板/命名规则）。
